# Архитектура HandDraw ESP

## Общая схема

HandDraw ESP разделяет подготовку изображения и управление движением. Проект не заменяет планировщик FluidNC и не выполняет тяжёлую обработку графики в задаче реального времени ESP32.

```text
телефон / компьютер
  браузер
    текст / SVG / растр
      полилинии в миллиметрах
        анализ и предпросмотр
          G-code
            WebDAV → SD ESP32
              FluidNC → STEP/DIR + RC-servo
```

WebUI находится во flash ESP32, поэтому система автономна. JavaScript выполняется на устройстве, открывшем страницу.

## Ответственность FluidNC

- планирование скорости и ускорения;
- синхронные STEP/DIR для X и Y;
- homing, координаты и программные границы;
- RC-servo в роли оси Z;
- выполнение G-code с SD/flash;
- realtime-пауза, продолжение и reset;
- HTTP, WebDAV и WebSocket;
- выдача положения, подачи и прогресса задания.

## Ответственность HandDraw WebUI

- однолинейный текст и пользовательские шрифты;
- пресеты человеческого почерка;
- импорт SVG;
- преобразование растра в контуры и штриховку;
- профили пишущих инструментов;
- размещение на A4 и поворот альбомного макета;
- сокращение холостого хода;
- анализ сложности и ограничений инструмента;
- предпросмотр и локальная симуляция;
- генерация G-code;
- проверенная запись на SD;
- мастер физической подготовки и запуска.

Подробное обоснование: [`FIRMWARE_AND_GCODE.md`](FIRMWARE_AND_GCODE.md).

## Единая модель траектории

После любого источника используется структура:

```js
[
  [ {x: 10.0, y: 12.0}, {x: 20.0, y: 15.0}, ... ],
  [ {x: 48.0, y: 22.0}, {x: 48.0, y: 36.0}, ... ]
]
```

Координаты заданы в миллиметрах от верхнего левого угла физически портретного листа. Один вложенный массив — непрерывный штрих. Между массивами перо поднимается.

Эта модель является источником для:

- SVG-предпросмотра;
- габаритов;
- статистики;
- проверки границ;
- оптимизации;
- симуляции;
- G-code.

Поэтому предпросмотр не может незаметно расходиться с заданием из-за отдельного конвертера.

## Текст и почерк

Формат шрифта хранит открытые штрихи, ширину продвижения и несколько вариантов знака. Раскладка применяет:

- высоту и коэффициент ширины;
- интервалы;
- наклон;
- масштаб отсутствующих строчных;
- небольшое воспроизводимое смещение;
- детерминированный выбор варианта.

Встроенный рукописный режим создаёт несколько смягчённых вариантов технических глифов. Пользовательский редактор позволяет заменить отдельные знаки собственными жестами.

## SVG

Файл разбирается браузером. Для видимых геометрических элементов браузер вычисляет полную матрицу преобразования и длину, после чего путь сэмплируется через `getPointAtLength()` и упрощается алгоритмом Рамера—Дугласа—Пекера.

Количество точек ограничивается до передачи в общую модель.

## Растр

Яркость пикселя переводится в относительную темноту. Реализованы:

- линии под произвольным углом;
- второй слой перекрёстной штриховки в тёмных областях;
- контур бинарного поля;
- комикс-режим: контур плюс два разреженных направления тени.

Растровая обработка выполняется в браузере. Шаг в миллиметрах ограничивает физическую плотность линий и число точек.

## Профили инструментов

Профиль является набором стартовых ограничений, а не сменой прошивки. Он задаёт скорости, выдержки, направление оптимизации, допустимую длину штриха, предпочтительный растр и текстовый пресет.

Направленное перо запрещает разворот штриха. Если пользователь задаёт повторный проход, генератор поднимает перо, возвращается к началу и снова выполняет линию вперёд.

## Оптимизация

Используется быстрая эвристика ближайшего следующего штриха. Для симметричных инструментов сравниваются оба конца. Для пера с тушью направление исходной линии сохраняется.

Оптимизация меняет только порядок и разрешённое направление штрихов, но не их форму.

## G-code и оценка

Генератор выдаёт метрический абсолютный G-code с отдельными выдержками после опускания и подъёма. Для каждого исходного штриха сохраняется диапазон байтов в файле. Процент SD-задания сопоставляется с этими диапазонами для подсветки прогресса.

Оценка времени включает длину рисования, холостой ход и выдержки. Она не является полной динамической моделью каждого разгона FluidNC.

## Связь с контроллером

| Операция | Интерфейс |
|---|---|
| команды и realtime | WebSocket `arduino`; HTTP `/command` как резерв |
| состояние | отчёты `<Idle|MPos:...>` каждые 500 мс |
| создание `/jobs` | WebDAV `MKCOL /sd/jobs` |
| запись файла | `PUT /sd/jobs/<name>` |
| проверка записи | обратный `GET` и сравнение числа байтов |
| запуск | `$SD/Run=/jobs/<name>` |
| пауза / продолжение / сброс | `!`, `~`, `Ctrl-X` |

Имя файла приводится к короткому ASCII-варианту.

## Состояние безопасности WebUI

Подтверждения хранятся только в текущем сеансе страницы. Изменение макета или профиля сбрасывает загруженный файл и проверки, зависящие от него. Запуск разрешается только при выполнении полного набора условий.

WebUI не заменяет аппаратную безопасность. Потеря Wi-Fi, зависание браузера или сбой ESP32 могут сделать программную кнопку недоступной, поэтому 12 В должны отключаться аппаратно.

## Автономная сборка

`scripts/build_webui.py`:

1. восстанавливает/проверяет отслеживаемые исходники;
2. встраивает CSS, JavaScript и шрифт;
3. проверяет отсутствие runtime-зависимостей;
4. создаёт `dist/index.html`;
5. детерминированно создаёт `dist/index.html.gz`;
6. записывает размеры и SHA-256 в `dist/manifest.json`.

Один сжатый файл упрощает обновление flash и исключает CDN.

## Машинные координаты и протокол команд

Внутренняя геометрия хранится в координатах листа. Перед генерацией G-code применяется профиль установки бумаги: номинально X 7,5 мм и Y 9 мм для центрированного A4 в поле 225 × 315 мм. Проверочная рамка использует тот же преобразователь, поэтому не может расходиться с основным заданием.

Команды FluidNC разделены на два канала. Обычные строки помещаются в последовательную очередь и требуют ответа `ok`; `error`, `ALARM`, тайм-аут или разрыв соединения отменяют продолжение последовательности. Realtime-байты состояния, паузы, продолжения и reset отправляются вне очереди. XY-переходы генерируются как `G1 F…`, чтобы скорость инструмента действительно ограничивала холостой ход.
